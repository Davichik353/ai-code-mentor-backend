# Условия публичного запуска

Код и тесты сами по себе не закрывают эксплуатационные действия.

| Проверка | Что требуется |
|---|---|
| История Git | Очистить все ветки, проверить отсутствие базы и `.env`; GitHub cached/PR refs — через Support |
| Секреты | Владелец перевыпускает раскрытые ключи и JWT_SECRET, проверяет последствия утечки |
| API | Один worker, корректные доверенные proxy; проверить сетевые лимиты с общей школьной сети |
| Почта | Настроить SMTP и отправить/получить настоящее письмо; проверить вход после восстановления |
| Публичный режим | PUBLIC_LAUNCH=true и REQUIRE_EMAIL_VERIFICATION=true; без SMTP запуск запрещён |
| База | Turso с отдельным токеном; SQLite и snapshots вне checkout |
| Резервирование | Отдельный ключ шифрования и отдельный токен чтения; включить задачу и проверить первый запуск |
| Данные | Публикуемая политика, контакт abddavlat3@gmail.com, согласование учебного пилота |
| Пилот | Даты, преподаватель, группа и реальные результаты ещё нужны |
| Экономика | Токены, актуальные тарифы моделей, активные ученики, расходы и курс ещё нужно измерить |

## Автоматические резервные копии

Workflow `.github/workflows/backup.yml` запускается ежедневно в 01:15 UTC (06:15 Ташкент), только если repository variable `BACKUPS_ENABLED=true`. Секреты GitHub Actions: `TURSO_DATABASE_URL`, `TURSO_BACKUP_TOKEN` (отдельный токен чтения), `BACKUP_ENCRYPTION_KEY` (Fernet). Их значений в коде нет; задача **не активна**, пока эти настройки не внесены.

Ключ создайте через `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` и храните отдельно от файлов резервных копий. Потеря ключа означает невозможность восстановления. В Actions загружается только зашифрованный файл, срок хранения 7 дней. При каждом запуске выполняется восстановление в отдельный временный файл и integrity check. Для больших баз заменить загрузку всей БД в память провайдерским backup/export.

Локально с переменными окружения:

```bash
python scripts/backup_database.py backup --output /private/backup.fernet
python scripts/backup_database.py restore --source /private/backup.fernet --output /private/restored.sqlite3
```

Приложение не перезаписывает существующие файлы. Восстановление в работающую базу автоматически не выполняется. Перед переключением: закрыть запись, проверить таблицы/число записей, повторно применить запросы удаления, сменить одноразовые/сессионные секреты при необходимости, затем открыть доступ. На бесплатном Render локальный файл резервной копией не считается.
