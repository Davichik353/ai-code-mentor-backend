# Учебный сценарий для пилота

## Что реализовано
- Самостоятельный выбор режима ученика/преподавателя для создания собственной группы. Права внутри каждой группы зависят от её владельца: вошедший по коду участник остаётся учеником этой группы даже после переключения общего режима. Роль не подтверждает профессиональную квалификацию.
- Группы с приглашением по коду и библиотека заданий по основам, условиям, циклам, строкам, спискам и логике. У упражнений есть уровень сложности и версии для Python/JavaScript, подсказки и проверочные примеры. Выдавать задания группе может только её владелец; повторная выдача того же упражнения в ту же группу возвращает 409. Ранее выданные задания сохраняются.
- «Исправь сам»: три последовательные подсказки. Пример решения закрыт до открытия подсказок и объяснения собственной попытки (не менее 20 символов). Преподавателю доступен пример для проверки.
- Мини-защита: объяснение алгоритма и граничного случая, изменённый код по дополнительному условию и объяснение изменения. Проверяет преподаватель.
- Кабинет преподавателя: участники, попытки, последние проваленные тесты по ученикам, принятие/возврат на доработку с комментарием. Неуспешные тесты не позволяют принять попытку.
- Учебные материалы и интерфейс кабинета на русском и узбекском (латиница); словарь пяти терминов. API /analyze принимает response_language: ru, uz, en и передаёт язык в Gemini.
- Портфолио принятых заданий с добровольной публикацией и отключением ссылки. Публично видны имя, описание, названия заданий, язык программирования и дата проверки. Почта, исходный код, ответы защиты и группа не выдаются.

Подсказки к упражнениям подготовлены заранее и не требуют Gemini. Свободный AI-анализ в основном редакторе использует настоящий Gemini; его качество зависит от модели. Это два отдельных сценария.

## Запуск и проверка
Использовать прежние requirements.txt, Python 3.11 и постоянный JWT_SECRET. Новых зависимостей нет. DATABASE_PATH задаёт путь SQLite. При старте init_db добавляет таблицы learning_*; существующие данные сохраняются. Сделать резервную копию базы до обновления. Удаление аккаунта удаляет его учебные данные; удаление аккаунта преподавателя также удаляет принадлежащие ему группы и их задания/попытки.

Запуск из backend: `python -m uvicorn main:app --host 127.0.0.1 --port 8000`.
Frontend запускать из отдельного репозитория ai-code-mentor-frontend на порту 8080. Настроить FRONTEND_ORIGINS для этого origin. Открыть «Учебный кабинет». Маршрут backend /app перенаправляет на основной frontend; отдельного HTML-интерфейса в backend больше нет.

Проверки backend: `python -m unittest discover -s tests -v`.
Проверки браузера — в frontend/tests/learning-flow.cjs и exercise-runtime.cjs. Нужны Playwright, Chromium, работающий API и доступ к CDN Pyodide. Тесты создают отдельные аккаунты и удаляют их после сценария; запускать на тестовой базе. Не запускать на рабочей базе организации.

## API
Все маршруты ниже начинаются с /learning. Кроме публичного портфолио, требуется Bearer JWT.

| Метод и путь | Назначение |
| --- | --- |
| GET, POST /profile | Режим, язык, описание, публикация портфолио |
| GET /templates, /glossary | Библиотека без готовых ответов; словарь |
| GET, POST /groups | Мои группы / создать группу |
| POST /groups/join | Вступить: {"code":"код"} |
| GET /groups/{id} | Задания с категорией/уровнем; участники и отчёты только владельцу; can_manage указывает права в этой группе |
| POST /groups/{id}/assignments | Выдать: {"template_id":"sum-py"} |
| GET /assignments/{id} | Условие, тесты, открытые подсказки, свои попытки; can_manage и can_submit отделяют просмотр преподавателя от сдачи учеником |
| POST /assignments/{id}/hints | Открыть следующую подсказку |
| POST /assignments/{id}/solution | Пример после reflection |
| POST /assignments/{id}/submissions | Исходный код, результаты тестов, объяснение и изменённый код |
| GET /submissions/{id} | Попытка только автору и владельцу группы |
| POST /submissions/{id}/review | approved / needs_revision и feedback от преподавателя |
| GET /portfolio | Моё портфолио |
| GET /portfolios/{slug} | Публичное портфолио только после включения |

## Границы этой версии
Результаты тестов приходят из браузера и могут быть подделаны. Сервер сравнивает вывод с ожидаемым, но не подтверждает выполнение программы: verification=browser_report_unverified, статус всегда pending_review. После ручной проверки преподавателем задание может попасть в портфолио. Это не антиплагиат, экзаменационная система, проверка квалификации преподавателя или официальный сертификат навыков.

Код не выполняется на сервере. В браузере доступны Python/Pyodide и JavaScript Worker, ввод/вывод, ограничение времени и остановка. Исполнение изменённого кода доступно ученику, а результат мини-защиты проверяет преподаватель вручную. Не запускать чужой неизвестный код: Worker не является виртуальной машиной с полной сетевой и ресурсной изоляцией.

Проверка stdout игнорирует пробелы по краям. Для каждого задания — не более 50 попыток на ученика; на преподавателя — не более 20 групп; на группу — не более 100 заданий. Приглашение по коду считается согласием преподавателя на вступление; код не следует публиковать. Код приглашения не виден ученикам в API. Владение другой группой или переключение режима на «Преподаватель» не даёт участнику прав выдачи и проверки заданий в группе, куда он вошёл по коду. Самостоятельная сдача и принятие собственной работы владельцем задания запрещены.

Для нескольких экземпляров нужны общий лимитер и стратегия хранения. До публичного запуска нужны политика данных, резервное копирование/восстановление, управление преподавателями и пилот с реальной учебной группой. Перевод на узбекский стоит проверить с преподавателем-носителем языка. Миграции, публикация сайта и реальный образовательный эффект не подтверждаются одними автотестами.
