## Инцидент с историей Git

В публичной истории находились SQLite с аккаунтами и работами и файл `.env`. Это потенциальное раскрытие персональных данных и секретов. Приватная резервная копия сохранена вне checkout. База, `.env`, Windows `venv` и мусор исключаются из всех публикуемых веток истории бэкенда; история переписывается.

Переписывание не отзывает скачанные копии, форки и GitHub cached/PR refs. Владелец должен:

1. Сменить все ключи, когда-либо находившиеся в `.env`: Gemini, SMTP, JWT и другие, если они были там. Не переносить старые секреты в новый файл.
2. Проверить доступы у провайдеров; отдельно отозвать управляющие токены, опубликованные ранее в чате. Не удалять рабочий отдельный токен базы до выпуска замены.
3. Считать парольные хеши раскрытыми: заменить JWT_SECRET, предложить пользователям сменить пароли и оценить уведомление затронутых людей. Письма без согласования не отправляются.
4. Обратиться в GitHub Support для удаления cached views и доступных PR refs с чувствительными файлами. Сообщить сотрудникам, что старые клоны нельзя пушить обратно; клонировать заново.

## Механизмы приложения

- Общие per-IP лимиты API и более строгие лимиты auth, `429` с `Retry-After`.
- Ограничение тела запроса 64 KiB, в том числе при chunked передаче.
- Ограничение входа также по нормализованному хешу email; одинаковая проверка хеша для отсутствующего аккаунта.
- PBKDF2 с индивидуальной солью; новый пароль не меньше 10 символов и не длиннее 256.
- Восстановление по случайному одноразовому токену на 15 минут; в базе только SHA-256. Смена пароля отзывает ранее выданные JWT через версию сессии.
- Ответ восстановления не сообщает, зарегистрирован ли адрес. Токен находится во фрагменте ссылки, frontend сразу убирает его из адресной строки.
- Суточные квоты AI по пользователю и всему сервису; учитываются и неудачные запросы. Лимит вызовов модели может быть выше числа анализов из-за fallback — это отражено в учёте токенов.
- Авторизация на личной истории и группах; портфолио публикуется только по выбору пользователя.

Ограничения: сетевой лимитер рассчитан на один процесс; перед горизонтальным масштабированием нужен общий счётчик. Защита не заменяет аудит, мониторинг и ротацию ключей. Состояние SMTP, активность backups и поведение настоящего внешнего почтового провайдера проверяются отдельно от unit-тестов.
