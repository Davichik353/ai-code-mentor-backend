# AI Code Mentor — backend

AI Code Mentor — учебная платформа для начинающих программистов, преподавателей и учебных центров.
Ученики выполняют задания, запускают код и получают постепенные подсказки на русском или узбекском.
Мини-защита просит объяснить решение и изменить код: преподаватель получает материал для проверки понимания.
Рабочий сценарий объединяет группу, задание, практику и проверку; [демо доступно в браузере](https://ai-code-mentor-frontend-iota.vercel.app).

**Статус:** работающий прототип. Реальный учебный пилот и измеренная себестоимость пока не подтверждены. Подготовка к публичному запуску описана в [LAUNCH.md](LAUNCH.md).

## Возможности и границы

FastAPI API: аккаунты, анализ кода, личная история, группы, упражнения, подсказки, мини-защита и добровольное портфолио. Python/JavaScript выполняются в браузере основного фронтенда. Сервер произвольный код учеников не запускает.

Проверка признаков AI ищет явные сведения о происхождении кода; она не устанавливает авторство. Результаты браузерных тестов проверяет преподаватель. Оценка Gemini — учебная подсказка, не объективная оценка знаний.

## Локальный запуск

Нужны Python 3.11+ и отдельный checkout frontend; в `runtime.txt` закреплён Python 3.11.9. Создайте окружение вне репозитория:

```bash
python3 -m venv "$HOME/.venvs/ai-code-mentor"
source "$HOME/.venvs/ai-code-mentor/bin/activate"
pip install -r requirements-dev.txt
cp .env.example .env
```

В локальном `.env` задайте случайный `JWT_SECRET` (`python -c "import secrets; print(secrets.token_urlsafe(48))"`). Для реального анализа нужен `GOOGLE_API_KEY`. Без него API честно возвращает недоступность анализа. Для локальной разработки без SMTP явно задайте `REQUIRE_EMAIL_VERIFICATION=false`; это режим демонстрации.

```bash
uvicorn main:app --host 127.0.0.1 --port 8000
# В другом терминале, из checkout frontend:
python3 -m http.server 8080
```

SQLite по умолчанию хранится в `~/.local/share/ai-code-mentor/code_mentor.db`, вне checkout. Можно указать абсолютный `DATABASE_PATH` вне репозитория. В Render используется удалённая Turso: задайте `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `REQUIRE_REMOTE_DATABASE=true`. Для используемой в проекте базы укажите URL с префиксом **`turso://`**: он выбирает драйвер `turso_serverless`. Префикс **`libsql://`** выбирает драйвер `libsql` и предназначен для совместимой базы libSQL. Префиксы не взаимозаменяемы: используйте URL, выданный для конкретной базы. PostgreSQL этим приложением не используется.

## Проверки

```bash
python -m unittest discover -s tests -v
```

Временные тестовые базы находятся вне Git. Тесты модели используют mock; это проверка интеграционного контракта, а не доказательство эффективности с учениками. Совместимость SQL дополнительно проверяется реальным локальным драйвером libSQL. Порядок живого пилота — [PILOT.md](PILOT.md).

## Развёртывание

Основной frontend размещён на Vercel, backend — Render, данные — Turso. `/` отдаёт описание API, `/app` перенаправляет на основной сайт. Дублирующего HTML-интерфейса здесь нет.

Разворачивайте **один worker**: общий сетевой лимитер хранится в памяти процесса. Суточные лимиты AI находятся в базе и переживают перезапуск. Для нескольких экземпляров нужен общий edge/Redis-лимитер. Настройте доверенные proxy-адреса Uvicorn для Render; приложение само не доверяет произвольному `X-Forwarded-For`.

Для открытого запуска задайте `PUBLIC_LAUNCH=true`, `REQUIRE_EMAIL_VERIFICATION=true` и действующий SMTP. При неверной конфигурации публичный режим не запускается. Наличие кода восстановления не означает, что почта уже подключена.
